# پروتکل هوش مصنوعی و ابزارهای وایب‌متن (VibeMatn)

این راهنما چارچوب رسمی استانداردسازی متون فارسی، پیکربندی فایل `llms.txt` برای کراولرهای هوش مصنوعی، اجرای ارزیابی در خط فرمان و گیت‌هاب اکشن، و هدایت ایجنت‌های کدنویسی از طریق `AGENTS.md` و `CLAUDE.md` را تعریف می‌کند.

## ۱. پیکربندی فایل llms.txt در ریشه وب‌سایت

فایل `llms.txt` استانداردی سبک بر پایه مارک‌داون برای آگاه‌سازی مدل‌های زبانی بزرگ و کراولرهای هوش مصنوعی است تا محتوا و قوانین پردازش زبان پروژه را بدون مصرف غیرضروری توکن درک کنند.

### مسیر استقرار فایل
- فایل باید مستقیما در آدرس `https://yourdomain.com/llms.txt` در دسترس باشد.
- در پروژه‌های Next.js یا Astro یا Vite: فایل را داخل پوشه `public/llms.txt` قرار دهید.
- در وب‌سرورهای Nginx یا Apache: فایل استاتیک را در ریشه وب‌سایت سرو کنید.

### نمونه استاندارد llms.txt منطبق بر پروتکل وایب‌متن

```markdown
# نام پروژه // llms.txt
> راهنمای رسمی درک محتوا و قوانین پالایش متن فارسی برای هوش مصنوعی

این فایل چارچوب تولید محتوا و قواعد نگارش فارسی در این پروژه را مشخص می‌کند. تمام مدل‌های پردازش زبان باید از قواعد زیر پیروی کنند:

## قواعد قطعی نگارش متن فارسی
۱. حذف افعال اداری فسیل:
- استفاده از «می‌باشد»، «می‌گردد»، «به شمار می‌رود»، «محسوب می‌شود» و «تلقی می‌گردد» ممنوع است. فقط از «است»، «شد» و «کرد» استفاده شود.

۲. حذف عبارت‌های زائد و فیلرها:
- عبارت‌های «لازم به ذکر است»، «شایان ذکر است»، «پرواضح است که» و «نکته حائز اهمیت این است» باید کاملا حذف شوند. اصل گزاره بدون مقدمه بیان شود.

۳. عدم استفاده از خط تیره بلند:
- استفاده از ام‌دش یا خط تیره بلند ممنوع است. از کامای فارسی (،) یا جملات مستقل استفاده شود.

۴. رسم‌الخط و نیم‌فاصله:
- نیم‌فاصله در پیشوندهای فعلی (می‌شود، نمی‌کند) و نشانه‌های جمع (کاربران، داده‌ها) اجباری است.
- حروف «ی» و «ک» استاندارد فارسی به کار روند.

۵. اعداد و مبالغ:
- ارقام نمایشی در رابط کاربری و متن به زبان فارسی (۰ تا ۹) درج شوند.
- مبالغ با واحد «تومان» پس از عدد و با جداکننده هزارگان (٬) نوشته شوند: «۱۵۰٬۰۰۰ تومان».

## مستندات تفصیلی
- مستندات کامل قوانین: /docs/persian-rules.md
- پیکربندی ایجنت‌ها: /AGENTS.md
```

## ۲. استفاده از ابزار خط فرمان npx vibematn در ترمینال و گیت‌هاب اکشن

ابزار `vibematn` برای بازبینی، پالایش سریع و انسان‌سازی متن‌های خام تولیدشده توسط هوش مصنوعی طراحی شده است.

### استفاده در ترمینال محلی

```bash
# پالایش درجا یک متن کوتاه
npx vibematn "این محصول حائز اهمیت می‌باشد و نقش بسزایی ایفا می‌کند."

# انتخاب لحن محاوره‌ای (گفتاری)
npx vibematn --tone conversational "شما می‌توانید سفارش خود را ثبت نمایید."

# انتخاب لحن میکروکپی رابط کاربری
npx vibematn --tone ui-copy "جهت ورود کلیک کنید"

# پالایش مستقیم فایل مارک‌داون یا سند متنی
npx vibematn --file README.md
```

### یکپارچه‌سازی در خط لوله GitHub Actions

برای اطمینان از عدم ورود عبارات فسیل اداری یا خط تیره بلند به مخزن کد، گام بررسی متن را به فایل گردش‌کار اضافه کنید:

`.github/workflows/vibematn-lint.yml`:

```yaml
name: VibeMatn Quality Gate

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

jobs:
  lint-persian-text:
    runs-on: ubuntu-latest
    steps:
      - name: دریافت کد منبع
        uses: actions/checkout@v4

      - name: تنظیم نودجی‌اس
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: بررسی خطاهای نگارشی و افعال فسیل
        run: |
          echo "شروع بررسی متن‌های فارسی مخزن..."
          # بررسی عدم وجود ام‌دش
          if grep -rn --include="*.md" --include="*.json" --include="*.html" $'\xe2\x80\x94' .; then
            echo "خطا: کاراکتر ام‌دش در فایل‌ها یافت شد."
            exit 1
          fi

          # بررسی عدم وجود افعال فسیل اداری
          if grep -rnE --include="*.md" --include="*.html" "می‌باشد|می‌گردد|لازم به ذکر است|شایان ذکر است" .; then
            echo "خطا: افعال یا عبارات فسیل هوش مصنوعی در فایل‌ها یافت شد."
            exit 1
          fi

          echo "بررسی متون با موفقیت انجام شد."
```

## ۳. تنظیم AGENTS.md و CLAUDE.md در پروژه‌های تیمی

برای تثبیت کیفیت متون توسط دستیارهای هوش مصنوعی (مانند Claude Code، Codex، Cursor، Copilot و Hermes)، این بلوک را مستقیما در فایل `AGENTS.md` یا `CLAUDE.md` در ریشه مخزن قرار دهید.

### متن قابل تزریق به AGENTS.md / CLAUDE.md

```markdown
# ضوابط متن فارسی و استاندارد وایب‌متن

این پروژه برای کاربران فارسی‌زبان طراحی شده است. در هر پاسخی که تولید می‌کنید، قواعد زیر را بدون استثنا رعایت کنید:

## قوانین نگارشی و پالایش لحن
۱. حذف کلمات فسیل هوش مصنوعی:
- هرگز از «می‌باشد»، «می‌گردد»، «به شمار می‌رود»، «محسوب می‌شود» یا «تلقی می‌گردد» استفاده نکنید. معادل‌های زنده: «است»، «شد»، «کرد».
- فیلرهای اعلامی مانند «لازم به ذکر است»، «شایان ذکر است»، «پرواضح است» را کاملا حذف کنید و مستقیما اصل پیام را بنویسید.
- از مقدمه‌های کلیشه‌ای مانند «در دنیای پرشتاب امروز» یا نتایج کلیشه‌ای مانند «در نهایت می‌توان گفت» پرهیز کنید.

۲. خط تیره بلند:
- استفاده از ام‌دش یا خط تیره بلند در کل پروژه ممنوع است. به جای آن از کامای فارسی (،) یا جملات مستقل استفاده کنید.

۳. رسم‌الخط و کاراکترها:
- نیم‌فاصله (ZWNJ) را در افعال استمراری (می‌کند، نمی‌شود)، جمع‌ها (کاربران، پروژه‌ها) و صفات (بهتر، سریع‌ترین) رعایت کنید.
- فقط از حروف فارسی «ی» و «ک» استفاده کنید و حروف عربی «ي» و «ك» را قرار ندهید.
- نقل‌قول‌ها در داخل گیومه فارسی « » قرار گیرند.

۴. ارقام و مبالغ:
- ارقام نمایشی در رابط کاربری باید فارسی باشند (۰ تا ۹).
- مبالغ با واحد تومان بعد از رقم و جداکننده هزارگان درج شوند: ۲۵۰٬۰۰۰ تومان.

۵. استانداردهای میکروکپی:
- متن دکمه‌ها حامل نتیجه عمل باشد: «ثبت‌نام»، «ذخیره»، «ارسال». از نوشتن «کلیک کنید» خودداری کنید.
- پیام‌های خطا علت مشکل و اقدام بعدی را با لحنی محترمانه بیان کنند.
```

## چک‌لیست قبل از پایان کار
- عدم وجود افعال فسیل («می‌باشد»، «می‌گردد»).
- عدم وجود علامت ام‌دش در کل تغییرات.
- درستی نیم‌فاصله‌ها و فارسی بودن ارقام نمایشی.
- بررسی تطابق متن رابط کاربری با راهنمای وایب‌متن.
